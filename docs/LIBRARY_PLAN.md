# ReadStep 1,500권 라이브러리 기획과 진행 계획

> 작성 2026-11-20 · v0.9 · 기준 데이터: `data/levels.js`, `data/wordlist.js`, `docs/quota.csv`
> 이 문서의 숫자 가운데 **사용자 확정**과 **에이전트 설계값(잠정)**을 2절에서 나눠 적었다. 설계값은 시범 150권을 만든 뒤 실측으로 다시 정한다.

## 1. 목적과 대상

- 아시아 어린이(첫 시장은 중국)가 영어를 외국어로 배우며 읽는 단계별 영어책 1,500권.
- 화면과 책에 딸린 글은 영어. 모국어 도움은 선택 묶음(중국어 `?l1=zh`, 한국어 `?l1=ko`).
- 참고 서비스와 같은 책을 만들지 않는다. 구조, 이름, 배분, 소재를 우리 근거로 정한다(10절).

### 일정

시범 측정과 다시 짠 일정은 `docs/PILOT_REPORT.md`(2026-11-28). 요약:

- 실측: 10권 묶음 하나에 에이전트 작업 중앙값 87분(권당 약 9분, 사용자 대기 시간이 섞였을 수 있음). 작업한 날 하루 약 30권. 표지 중 사람 판단이 필요한 것 약 50%.
- 재지 못한 것: 비용, 쪽마다 장면 그림, 음성 파일, 3단계 이상 긴 글.
- 2단계(1~2단계 나머지 545권): 에이전트 작업 약 80시간. 사람 검수가 더 느림(검수자 1명, 주 10시간이면 1~2단계 전체 약 8~16주, 가정).
- 권장 순서: 표본 검수(레벨마다 2권, 표지 75장) → 반영 → 2단계 제작과 시범 검수를 함께 → 3단계 시범 10권으로 긴 글을 잰 뒤 3단계 이후 일정.

## 7. 책 한 권 제작 흐름 (10권 한 묶음)

1. 기획표: 레벨, 갈래, 주제, 지역, 시리즈, 파닉스 단계를 `docs/quota.csv`의 빈칸에서 고른다
2. AI 초안: 레벨 규격과 낱말 목록 안에서 쓴다. 제목은 참고 서비스 제목과 겹치지 않게
3. 검사기(`tools/check.html`): 오류 0건이 될 때까지 고친다
4. 다른 AI 모델의 교차 검수(읽기 전용)와 반영. 아래 "표본 검수에서 나온 규칙"을 검수 기준에 넣는다
5. 그림: 1~2단계는 SVG 낱말 그림(`data/pictures.js`)과 표지 장면 그림. 3단계부터 쪽마다 장면 그림
6. 음성: 시범까지는 브라우저 음성(미국식), 2단계부터 미리 만든 음성 파일
7. 확인 문제 5문항, 다시 세우기 문장 확인
8. 중국어 낱말 도움(`data/words-zh.js`)
9. 사람 검수: 1~2단계는 전수, 3단계부터 표본(10권 중 1권)
10. 공개: GitHub에 폴더별로 나눠 올리고 원격 파일과 대조

### 표본 검수에서 나온 규칙 (2026-11-28)

표본 20권(273줄)과 표지 83장을 AI 검수(독립 AI 검수 + 에이전트 확인)한 결과, 본문 28곳과 퀴즈 22곳을 고치고 표지 8장을 다시 그렸다(`docs/PILOT_REPORT.md` 10절). 이어 나머지 130권도 같은 방식으로 검수했다(11절). 같은 문제가 되풀이되지 않게 초안 단계부터 다음을 지킨다.

1. 시제: 한 책은 현재형이나 과거형 하나로 쓴다. 따옴표 안의 말만 예외. 파닉스 낱말을 맞추려고 과거형(got, came)을 끼워 넣지 않는다.
2. 퀴즈 보기: 세 보기의 형식을 맞춘다(감정을 물으면 세 보기 모두 감정 낱말). 정답만 문장이거나 길이가 다르면 형식으로 답이 드러난다.
3. 퀴즈 정답: 오답 보기가 본문의 다른 쪽에서 맞는 말이 되지 않게 한다(예: 염소가 빵도 먹었는데 "무엇을 가져갔나"에 빵을 오답으로 둠).
4. 퀴즈 유형: 본문에 그대로 있으면 detail, 순서를 물을 때만 seq, 본문에 없는 이유를 추론할 때만 infer.
5. 시리즈 설정: 인물 관계(Pam은 Sam의 동생이라 같은 반이 아님)를 `docs/series-bible.md`와 맞춘다.
6. 문화 사실: 명절 풍습은 실제와 맞춘다(물 축제에서 어른 손에 물을 조심히 붓는 쪽은 아이).
7. 안전과 생활 습관: 종이 등에는 촛불 대신 작은 전등, 고양이에게 우유 대신 먹이.
8. 자연스러운 영어: "went to the sand"(→ beach), "can not"(→ cannot), "in a bib"(→ has a bib), "a bit of bread"(→ a piece of)처럼 원어민이 쓰지 않는 말을 피한다.
9. 그림 낱말: 그 쪽의 중심 명사(사람, 동물, 물건)는 pictureWords에 넣는다.
10. 표지 프롬프트(아시아 소재): 삿갓, 불탑·사원, 도리이 같은 문, 전통 의상을 기본으로 넣지 않는다. 프롬프트에 "Everyday modern clothes. No conical hats, no pagodas, no temples, no stupas, no shrine gates, no traditional costumes."를 넣는다. 명절 장면에서만 그 명절에 맞는 옷과 장식을 쓴다.
11. 한 인물은 한 장면에 한 번만 나오게 한다(프롬프트에 "Only one ..."을 적는다).
12. 순서 퀴즈: "after the hen"처럼 쓰면 그 뒤의 것이 모두 답이 된다. "right after", "right before"로 쓴다. "last"도 그 뒤에 보기가 또 나오면 쓰지 않는다.
13. 질문 모양: "How is the tub?" 대신 "What is the tub like?", 감정은 "How does ... feel?"로 묻는다.
14. 안전과 생활 습관(7번에 더함): 자전거를 탈 때는 헬멧, 어린아이 혼자 물가에 가지 않기, 차 안에 숨지 않기, 낯선 개는 주인에게 묻고 만지기, 바닥에 떨어진 음식 먹지 않기, 오리에게 빵 주지 않기, 뜨거운 오븐은 어른과 함께.
15. 낱말 풀이는 낱말 하나에 하나만 있다. 뜻을 쓰거나 고칠 때 그 낱말이 나오는 모든 책을 찾아 쓰임을 모두 담는다(예: stand, still, ring).
16. 그림 낱말은 한 쪽에 3개까지(모바일). 수를 세는 책도 그림 수로 수를 맞추지 않는다.
17. 시리즈 정보글(S06)의 마지막 쪽 "Now I know!"는 그대로 두되, 다른 책에서 이야기 밖 "I"가 갑자기 나오지 않게 한다.

원칙
1. 사이트는 드라이브 파일을 직접 쓰지 않는다. 드라이브 웹 호스팅은 2016년에 끝났고, 한 파일을 짧은 시간에 많이 받으면 막히며, 중국 본토에서는 드라이브가 막혀 있다.
2. 원본은 드라이브에만 둔다. GitHub에는 사이트가 쓰는 작은 파일(WebP, MP3)과 목록만 둔다. GitHub는 레포를 1GB 이하, 늦어도 5GB 이하로 두라고 권한다.
3. 책 글과 데이터의 기준본은 GitHub(`data/`)다. 검사기가 이 파일을 읽기 때문이다. 드라이브에는 배포할 때마다 복사본만 둔다.
4. 파일 이름은 두 곳에서 같다. `<책 id>-cover`, `<책 id>-p01` ... 원본은 `.png`, 웹용은 `.webp`.

```
  04_Prompts_Logs/     그림 프롬프트, 생성 실패와 거절 기록
  05_Review/           사람 검수 시트(구글 시트), 검수 결과
  06_Releases/         배포 버전별 스냅샷(사이트 전체 zip)
  07_Reference/        참고 서비스 분석 자료(공개 레포에 두지 않을 것)
  99_Archive/          쓰지 않게 된 그림, 이전 버전
```
번호를 붙인 폴더 이름은 같은 드라이브의 `ELT Image Library`(01_Style_Guide ...)와 맞춘 것이다.

### 8.3 운영 레포 나누기 (GitHub Pages 사이트 하나 1GB 이하)

1,500권 웹용 추정(에이전트 계산: 쪽마다 장면 그림 1장 약 130KB, 표지 약 80KB, 음성은 분당 110낱말·48kbps, 천천히 듣기는 재생 속도로 처리):

| readstep-media-s12 | 1~2단계 장면 그림과 음성 | 약 0.85GB |
| readstep-media-s3 | 3단계 | 약 0.74GB |

### 8.4 작업 흐름

1. 제작: 그림을 만들면 원본 PNG는 드라이브 `02_Art_Originals/<레벨>/`, 웹용 WebP는 운영 레포에 올린다. manifest.csv에 두 위치를 적는다.
2. 검수: 검수표를 드라이브 `05_Review`의 구글 시트로 둔다. 검수자(1명)는 시트에서 판정하고, 에이전트가 결과를 GitHub 데이터에 반영한다.
3. 배포: GitHub Pages로 배포하고, 버전마다 사이트 전체를 `06_Releases`에 zip으로 남긴다.
4. 중국 서비스: ICP 신고 뒤 중국 안 저장소와 CDN에 `06_Releases`의 파일을 올리고 앱의 주소 설정을 바꾼다.

### 8.5 옮기는 순서

진행(2026-11-27): 1~4번 끝. 드라이브 `ReadStep/` 폴더 9개와 원본 레벨 폴더 10개를 만듦. 원본 149장을 복사하고 모두 한 바이트씩 대조함. 검수표 2,430줄을 구글 시트(`05_Review`)로 옮기고 모든 칸을 원본과 대조함. 판정 칸에 통과·고침·빼기 목록을 넣음. 앞으로 사람 검수의 기준본은 이 구글 시트이고, 새 묶음의 검수 줄은 에이전트가 시트에 덧붙인다. 공개 레포의 검수표(docs/review-sheet.csv)는 퀴즈 정답이 들어 있어 2026-11-27에 뺐다(사용자 결정). 교사와 학부모는 사이트의 Teachers, Parents 화면에서 책별 정답표를 본다. 남은 것: 5번(장면 그림과 음성 제작 때).

1. 드라이브에 `ReadStep/` 폴더 구조를 만든다.
2. readstep-art의 `original/` PNG(시범 149장, 약 273MB)를 `02_Art_Originals/<레벨>/`로 복사하고 개수와 크기를 대조한다. manifest.csv에 드라이브 위치 칸을 더한다.
3. 다음 그림부터 원본은 드라이브에만 둔다. readstep-art의 기존 PNG는 지우지 않는다(지워도 Git 기록에 남아 레포 용량이 줄지 않음).
4. 검수표(docs/review-sheet.csv)를 구글 시트로 옮긴다. 공개 레포의 검수표(퀴즈 정답 포함)를 뺄지는 사용자가 정한다.
5. 장면 그림과 음성을 만들기 시작할 때 readstep-media-* 레포를 만든다.

### 8.6 주의할 점

- 드라이브는 개인 계정 하나에 묶여 있다. 요금제를 끊어 용량을 넘으면 새 파일을 올릴 수 없다. 사이트는 GitHub 파일로 돌아가므로 영향이 없다.
- 가족 3명과 같은 20TB를 나눠 쓴다.
- GitHub Pages는 한 달 전송량 약 100GB가 권장 한도이고, 상업 서비스 용도는 약관상 맞지 않는다. 유료 출시 전에는 별도 호스팅으로 옮긴다.
- GitHub Pages와 드라이브 모두 중국 본토에서 막히거나 느리다. 중국 출시 전에는 ICP 신고와 중국 안 CDN이 필요하다.
