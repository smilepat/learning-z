# ReadStep 1,500권 라이브러리 기획과 진행 계획

> 작성 2026-11-20 · v0.9 · 기준 데이터: `data/levels.js`, `data/wordlist.js`, `docs/quota.csv`
> 이 문서의 숫자 가운데 **사용자 확정**과 **에이전트 설계값(잠정)**을 2절에서 나눠 적었다. 설계값은 시범 150권을 만든 뒤 실측으로 다시 정한다.

## 1. 목적과 대상

- 아시아 어린이(첫 시장은 중국)가 영어를 외국어로 배우며 읽는 단계별 영어책 1,500권.
- 화면과 책에 딸린 글은 영어. 모국어 도움은 선택 묶음(중국어 `?l1=zh`, 한국어 `?l1=ko`).
- 참고 서비스와 같은 책을 만들지 않는다. 구조, 이름, 배분, 소재를 우리 근거로 정한다(10절).

- 주제는 12개 자체 분류(`data/levels.js` TOPICS). 한 단계 안에서 한 주제가 5~12%가 되게 맞춘다(권장).
- 아시아 소재: 동아시아, 동남아시아, 남아시아의 생활, 명절, 도시, 옛이야기를 고르게. 세계 공통: 동물, 자연, 과학, 몸과 건강, 음식, 학교와 친구, 감정, 세계의 옛이야기. 한 나라에 치우친 소재(미국 역사, 미국 명절 등)는 넣지 않는다.

## 5. 1~2단계 갈래와 파닉스 해독책

- Word Spotter 갈래 세 개: 듣기 먼저 그림책(listen) 100권, 파닉스 해독책(phonics) 80권, 반복 문장책(pattern) 150권.
- Sentence Builder: 파닉스 해독책 120권, 이야기와 정보글(story) 270권.
- 파닉스 해독책 5단계 규격: `docs/phonics-track.md`. 해독 가능 비율 85% 이상을 검사기가 확인한다.

## 7. 책 한 권 제작 흐름 (10권 한 묶음)

1. 기획표: 레벨, 갈래, 주제, 지역, 시리즈, 파닉스 단계를 `docs/quota.csv`의 빈칸에서 고른다
2. AI 초안: 레벨 규격과 낱말 목록 안에서 쓴다. 제목은 참고 서비스 제목과 겹치지 않게
3. 검사기(`tools/check.html`): 오류 0건이 될 때까지 고친다
4. 다른 AI 모델의 교차 검수(읽기 전용)와 반영
5. 그림: 1~2단계는 SVG 낱말 그림(`data/pictures.js`)과 표지 장면 그림. 3단계부터 쪽마다 장면 그림
6. 음성: 시범까지는 브라우저 음성(미국식), 2단계부터 미리 만든 음성 파일
7. 확인 문제 5문항, 다시 세우기 문장 확인
8. 중국어 낱말 도움(`data/words-zh.js`)
9. 사람 검수: 1~2단계는 전수, 3단계부터 표본(10권 중 1권)
10. 공개: GitHub에 폴더별로 나눠 올리고 원격 파일과 대조

## 8. 그림, 음성, 저장 (2026-11-27 다시 세움)

사용자 방향(2026-11-27): 구글 드라이브는 보관용, GitHub는 운영용. 드라이브는 Google AI Ultra 요금제 20TB(eltkorea@gmail.com, 2026-11-27 기준 144.57GB 사용, 가족 3명과 함께 씀).

### 8.1 역할 나누기

| 어디 | 무엇을 | 공개 범위 |
|---|---|---|
| 구글 드라이브 `ReadStep/` | 원본 그림(PNG), 음성 원본(WAV), 프롬프트와 생성 기록, 사람 검수 시트, 배포 스냅샷, 참고 자료 분석 | 비공개. 검수자에게는 검수 폴더만 공유 |
| `smilepat/learning-z` | 서비스 코드, 게시한 책 데이터, 검사기, 표지 WebP | 공개(GitHub Pages) |
| `smilepat/readstep-media-*` (새로 만듦) | 장면 그림 WebP, 음성 MP3. 단계별로 레포를 나눔 | 공개(GitHub Pages) |
| `smilepat/readstep-art` | 그림 목록(manifest.csv: 드라이브 파일 ID와 웹 파일 경로), 변환 규칙 | 비공개 |

원칙
1. 사이트는 드라이브 파일을 직접 쓰지 않는다. 드라이브 웹 호스팅은 2016년에 끝났고, 한 파일을 짧은 시간에 많이 받으면 막히며, 중국 본토에서는 드라이브가 막혀 있다.
2. 원본은 드라이브에만 둔다. GitHub에는 사이트가 쓰는 작은 파일(WebP, MP3)과 목록만 둔다. GitHub는 레포를 1GB 이하, 늦어도 5GB 이하로 두라고 권한다.
3. 책 글과 데이터의 기준본은 GitHub(`data/`)다. 검사기가 이 파일을 읽기 때문이다. 드라이브에는 배포할 때마다 복사본만 둔다.
4. 파일 이름은 두 곳에서 같다. `<책 id>-cover`, `<책 id>-p01` ... 원본은 `.png`, 웹용은 `.webp`.

### 8.2 드라이브 폴더

```
ReadStep/

  03_Audio_Masters/    <레벨>/<책 id>/ 녹음 또는 TTS 원본 WAV
  04_Prompts_Logs/     그림 프롬프트, 생성 실패와 거절 기록
  05_Review/           사람 검수 시트(구글 시트), 검수 결과
```

### 8.4 작업 흐름

1. 제작: 그림을 만들면 원본 PNG는 드라이브 `02_Art_Originals/<레벨>/`, 웹용 WebP는 운영 레포에 올린다. manifest.csv에 두 위치를 적는다.
2. 검수: 검수표를 드라이브 `05_Review`의 구글 시트로 둔다. 검수자(1명)는 시트에서 판정하고, 에이전트가 결과를 GitHub 데이터에 반영한다.
3. 배포: GitHub Pages로 배포하고, 버전마다 사이트 전체를 `06_Releases`에 zip으로 남긴다.
4. 중국 서비스: ICP 신고 뒤 중국 안 저장소와 CDN에 `06_Releases`의 파일을 올리고 앱의 주소 설정을 바꾼다.

### 8.5 옮기는 순서

진행(2026-11-27): 1~4번 끝. 드라이브 `ReadStep/` 폴더 9개와 원본 레벨 폴더 10개를 만듦. 원본 149장을 복사하고 모두 한 바이트씩 대조함. 검수표 2,430줄을 구글 시트(`05_Review`)로 옮기고 모든 칸을 원본과 대조함. 판정 칸에 통과·고침·빼기 목록을 넣음. 앞으로 사람 검수의 기준본은 이 구글 시트이고, 새 묶음의 검수 줄은 에이전트가 시트에 덧붙인다. 남은 것: 공개 레포의 검수표를 뺄지(사용자 결정), 5번(장면 그림과 음성 제작 때).

1. 드라이브에 `ReadStep/` 폴더 구조를 만든다.
2. readstep-art의 `original/` PNG(시범 149장, 약 273MB)를 `02_Art_Originals/<레벨>/`로 복사하고 개수와 크기를 대조한다. manifest.csv에 드라이브 위치 칸을 더한다.
3. 다음 그림부터 원본은 드라이브에만 둔다. readstep-art의 기존 PNG는 지우지 않는다(지워도 Git 기록에 남아 레포 용량이 줄지 않음).
4. 검수표(docs/review-sheet.csv)를 구글 시트로 옮긴다. 공개 레포의 검수표(퀴즈 정답 포함)를 뺄지는 사용자가 정한다.
5. 장면 그림과 음성을 만들기 시작할 때 readstep-media-* 레포를 만든다.

### 8.6 주의할 점

- 드라이브는 개인 계정 하나에 묶여 있다. 요금제를 끊어 용량을 넘으면 새 파일을 올릴 수 없다. 사이트는 GitHub 파일로 돌아가므로 영향이 없다.
- 가족 3명과 같은 20TB를 나눠 쓴다.
- GitHub Pages는 한 달 전송량 약 100GB가 권장 한도이고, 상업 서비스 용도는 약관상 맞지 않는다. 유료 출시 전에는 별도 호스팅으로 옮긴다.
- GitHub Pages와 드라이브 모두 중국 본토에서 막히거나 느리다. 중국 출시 전에는 ICP 신고와 중국 안 CDN이 필요하다.

## 11. 근거 자료

- 참고 서비스 공개 도서 목록: readinga-z.com/books/books-by-grade-level (2026-11-19, 가입 없이 공개 페이지만). 영어 레벨 도서 2,572판, 레벨별 집계는 사용자에게 CSV로 전달. 제목은 해시로만 `tools/ref-titles.js`에 저장.
